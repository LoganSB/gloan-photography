# SYSTEMS.md: Map of interconnected components

Keep this current. Rules for using it are in [AGENTS.md](AGENTS.md) (one hop only, each file once per task).

## Components

| ID | File(s) | Role |
|---|---|---|
| SERVER | `server.py` (entry point), `requirements.txt` + `gloan/` package | Flask + Gunicorn HTTP server, split by job (below) |
| SERVER-config | `gloan/config.py` | Paths, limits, regexes, logger |
| SERVER-storage | `gloan/storage.py` | `photos.json` + image files: validation, cleaning, scan, in-memory `RowsCache`, `available_rows` (skips index rows with no file) |
| SERVER-query | `gloan/query.py` | Filter/sort/page for `GET /api/photos` (`SORT_KEYS`) |
| SERVER-tags | `gloan/tags.py` | Cached `TagIndex` (rebuilt when `photos.json`/`photos/` change or `storage.index_generation()` bumps) and typo-tolerant search for `GET /api/tags` |
| SERVER-auth | `gloan/auth.py` | Multi-device WebAuthn Passkey verification (`cryptography` ES256), Cloudflare Turnstile verification, signed owner tokens (`data/session.key`), and login-lockout state |
| SERVER-handler | `gloan/handler.py` | Flask `app`, `Content-Security-Policy`, and HTTP routes (`Handler` config) |
| SERVER-cli | `gloan/cli.py` | Flags, password prompt, Gunicorn (1 worker, 8 threads) / Werkzeug start-up |
| SERVER-aitags | `gloan/aitags.py` | Low-cost / zero-cost AI tag bot (`gemini-2.5-flash-lite` free tier + local Pillow visual analyzer) triggered only on admin upload (`POST /api/photos`) and admin manual rescan (`POST /api/rescan`); records `aiTags` (5+ tags) in `photos.json` |
| SERVER-thumbtool | `gloan/thumbtool.py` | Launches `tools/make_thumbnails.py` in the background on owner request and tracks status |
| THUMB-TOOL | `tools/make_thumbnails.py`, `tools/requirements.txt` | Standalone Pillow utility that generates 480px JPEG tiles in `data/thumbs/` and records `thumb` in `photos.json` (run locally on demand, never auto-run on upload) |
| TESTS | `tests/test_gloan.py` | Unit, integration, cache, thumbnail-tool, and `static/*.js` ES module syntax test suite (`python3 -m unittest discover -s tests -v`) |
| FRONTEND | `index.html`, `static/app.css`, `static/api.js`, `static/gallery.js`, `static/lightbox.js`, `static/upload.js`, `static/search.js`, `static/app.js` | Single-page gallery and owner UI using native ES modules (no build step); talks to SERVER via `API` in `static/api.js` |
| DATA | `data/photos/`, `data/thumbs/`, `data/photos.json`, `data/passkey.json`, `data/session.key` | Image files, metadata, registered owner Passkey public key, and session signing key; path set by `GLOAN_DATA` |
| DOCKER-PROD | `Dockerfile`, `.dockerignore` | Production image (Cloud Run); copies `server.py`, `gloan/`, `static/`, `tools/` and `index.html`, and installs `requirements.txt` + `tools/requirements.txt` |
| DOCKER-DEBUG | `Dockerfile.debug`, `docker-compose.debug.yml` | Local debug container with debugpy on 5678, site on 8000 |
| VSCODE | `.vscode/launch.json`, `.vscode/tasks.json` | F5 starts DOCKER-DEBUG and attaches debugger |
| DEPLOY | `deploy.sh` | Cloud Run + Cloud Storage + Secret Manager deploy |
| DOCS | `README.md`, `AGENTS.md`, `SYSTEMS.md` | Documentation |

## Testing linked systems

- Run unit & JS syntax tests after every change: `python3 -m unittest discover -s tests -v`.
- Start with F5 (or `docker compose -f docker-compose.debug.yml up -d --build`) and open http://localhost:8000.
- Run the full suite inside the container (which includes Pillow): `docker exec gloan-debug python3 -m unittest discover -s tests -v`.
- Check: gallery loads, Admin login (`debugpassword`), upload, edit, delete, rescan, thumbnail generation, logout/expired session.
- Production image: `docker build -t gloan-test .` should succeed.
