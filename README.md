# Gloan

This is currently in stage one and is entirely AI generated with only minor human edits. You have been warned.

Landscape and macro photo gallery: static page (`index.html` + `static/app.css` + native ES modules in `static/*.js`, no build step) plus a small
Flask + Gunicorn Python backend (`server.py` entry point plus the `gloan/` package; `pip install -r requirements.txt`).

## Run

In Terminal:

```bash
cd ~/Documents/Gloan
python3 server.py
```

It asks you to choose an owner password (8+ characters, not shown as you type).
When it prints `Gloan on http://127.0.0.1:8000`, open that address in
your browser, click **Admin login**, enter the password, and upload. Visitors
can browse, filter and play the slideshow but cannot change anything.
Stop the server with `Ctrl+C`; the password is asked for again next start.

To skip the prompt, set `GLOAN_PASSWORD` in the environment (from a password
manager, for example) before starting.

Flags: `--host 0.0.0.0` to listen on your network, `--port N`.
Env: `GLOAN_DATA` moves the storage folder (default `./data`).

## Who can log in

Owner authentication uses **WebAuthn Passkeys (FIDO2)** (TouchID / FaceID / Windows Hello / YubiKey) protected by
**Cloudflare Turnstile** bot CAPTCHA (when `GLOAN_TURNSTILE_SITE_KEY` and `GLOAN_TURNSTILE_SECRET_KEY` are set) and
IP failure lockout (5 failures = 60s lockout). Your private key never leaves your device; only the ES256 public key
and credential ID are stored in `data/passkey.json`.

**Initial Passkey enrollment & debug password workaround:**
While `GLOAN_PASSWORD` is set in the environment (such as `debugpassword` in local Docker debugging, or on your first
Cloud Run deployment), the login modal also shows a temporary debug password box. Log in once with that password,
click **Register Passkey** in the footer, and complete your browser's Passkey prompt. Once `data/passkey.json` exists
and you have verified signing in with your Passkey, unset `GLOAN_PASSWORD` (or remove the marked
`DEBUG PASSWORD WORKAROUND` block in `gloan/auth.py`, `gloan/handler.py` and `static/app.js`) to disable password
authentication completely.

## Data

`data/photos/` holds the images, `data/thumbs/` holds the small tile images shown in the gallery (full-size files
load only in the full-screen popup), and `data/photos.json` holds each photo's title, tags, story and the `thumb`
link to its tile. Tiles are generated by `tools/make_thumbnails.py` (uses Pillow: `pip install -r tools/requirements.txt`),
either run locally on its own (`python3 tools/make_thumbnails.py`) or triggered on demand by the logged-in owner ("Generate thumbnails"
in the footer). Thumbnails are never generated automatically on upload so Cloud Run CPU time is not consumed unexpectedly.
Back up the `data/` folder and you have everything.

## Searching tags

The search box above the tag chips filters the gallery live and suggests tags as you type:
- **AND matching everywhere:** clicking multiple tag chips below the search bar or entering comma-separated terms in
  the search box requires photos to match **all** selected/searched tags.
- **Tab autofill & per-comma predictions:** typing `bry` suggests matching tags in alphabetical order (`bryce_fall`,
  `bryce_summer`, `bryce_winter`, …). Pressing **Tab** (or clicking a suggestion) completes the current term with a
  trailing comma (`bryce_fall, `) and immediately opens predictive suggestions for the next comma-separated term.
- **Wildcards & typos:** matching ignores case, accents and spaces/`_`/`-`; `*` and `?` work as wildcards (`*wint`
  matches `bryce_winter` and `arches_winter`; `*winter, bryce` matches only `bryce_winter`); and from 3 characters on,
  one typo is forgiven.

## Putting it online

The server speaks plain HTTP. Put it behind a TLS reverse proxy (Caddy, nginx,
Cloudflare Tunnel) before exposing it, or the password and token cross the
network in the clear.

## API

| Method | Path | Auth |
|---|---|---|
| GET | `/api/photos?page=0&size=10&sort=new&tags=a,b&match=any` (one page of photos, each with `added` ms timestamp and `size` bytes, plus `total`, `all`, `pages` and gallery-wide `tags` counts; `size` max 100; `sort` is `new`, `old`, `az`, `za`, `big` or `small`; `match` is `any` or `all`), `/photos/<id>.<ext>`, `/api/session` | public |
| GET | `/api/tags?q=text&limit=8` (tag suggestions, best first: `[{tag, count, match}]` where `match` is `exact`, `prefix`, `word`, `contains`, `wildcard`, `fuzzy` or `popular`; `limit` max 20) | public |
| POST | `/api/passkey/login/options`, `/api/passkey/login` (WebAuthn Passkey assertion + Turnstile `captchaToken`) -> `{"token"}` | public (5 failures = 60s lockout) |
| POST | `/api/passkey/register/options`, `/api/passkey/register` (stores ES256 public key in `data/passkey.json`) | owner (or first-time setup) |
| POST | `/api/login` `{"password","captchaToken"}` -> `{"token"}` *(debug workaround only; 404 when `GLOAN_PASSWORD` unset)* | public (5 failures = 60s lockout) |
| GET | `/thumbs/<id>.jpg` | public |
| GET | `/api/thumbnails` (job status: `running`, `exitCode`, `output`, `missing`) | owner |
| POST | `/api/thumbnails` (starts `tools/make_thumbnails.py` in the background) | owner |
| POST | `/api/photos` raw image body, `X-Title` / `X-Tags` URL-encoded headers | owner |
| PATCH | `/api/photos/<id>` `{"title","tags"}` | owner |
| DELETE | `/api/photos/<id>` | owner |

Owner calls send `Authorization: Bearer <token>`; tokens last 12 hours.

## Deploying to Google Cloud Run

Cloud Run's disk is wiped whenever an instance stops, so photos and `photos.json` live in a Cloud Storage
bucket mounted at `/data`. `deploy.sh` creates the bucket, stores the owner password in Secret Manager and
deploys from the `Dockerfile`:

```bash
PROJECT=my-gcp-project ./deploy.sh
```

It needs the `gcloud` CLI, signed in (`gcloud auth login`). The first run asks for the owner password.

Things to know:

- **One instance only** (`--max-instances=1`). The metadata file is edited under an in-process lock, so two
  instances could overwrite each other. It scales to zero when idle, so the first visit after a quiet spell is
  a little slower.
- **Client address.** Cloud Run puts the real client address last in `X-Forwarded-For`; the server reads that
  entry (for the login lockout, and for `--owner-ip` if you set it by running `OWNER_IP=1.2.3.4 ./deploy.sh`).
  If you later put a load balancer in front, add `--proxy-hops 2`.
- **Your domain.** `gcloud beta run domain-mappings create --service gloan --domain gloan.example.com --region REGION`
  prints the DNS records to add at your registrar; Google issues the HTTPS certificate itself.
- **HTTPS** is provided by Cloud Run, which is what the owner password needs on the public internet.
- **Adding photos by hand:** upload files to the bucket's `photos/` folder (console or
  `gcloud storage cp *.jpg gs://BUCKET/photos/`), then use "Scan folder for new photos" on the site.
- **Size limit:** Cloud Run rejects requests over 32 MB; uploads are capped at 25 MB anyway.
- **Changing the password:** add a new Secret Manager version
  (`gcloud secrets versions add gloan-password --data-file=-`) and redeploy.
- **Cost:** a personal gallery typically stays within the free tier; the bucket is the only always-on piece.

Flags added for this: `--proxy-hops N` and `--proxy-any-peer` (trust the proxy header from any peer, only safe
when the container is reachable solely through a managed proxy). `PORT` is honored as the default port.
